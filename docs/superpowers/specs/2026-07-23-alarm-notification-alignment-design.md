# 提醒时间与通知展示对齐设计

## 目标

关闭 `GAP-03`：为正常轮询、系统休眠恢复、设置变更、日程变更、实例排除和 Todo 完成建立统一的提醒重算入口；明确不会重复或永久漏发的时间边界；按用户时区生成保留未知时间语义的通知内容。

本设计只补齐进程存活期间的提醒调度。应用未运行或操作系统关机期间的跨进程补发不在范围内，也不引入持久化提醒队列。

## 核心语义

提醒检查使用左开右闭区间 `(lastCheckedAt, checkedAt]`：

- 提醒时间恰好等于本次检查时间时，本次触发。
- 提醒时间恰好等于上次成功检查时间时，不再触发。
- 只有候选查询与本轮通知处理成功后，才推进成功检查边界。
- 进程内去重键为 `occurrenceId + alarmAt`。重算相同结果不会重复通知；设置变化产生不同 `alarmAt` 时，它是新的提醒计算结果。

应用启动时以当前时间建立检查基线并计算未来候选，不追溯应用未运行期间的提醒。正常轮询每 30 秒检查一次；定时器延迟不会改变区间语义。

## 休眠恢复与补发

Electron 监听操作系统恢复事件。恢复后保留休眠前最后一次成功检查时间，并立即通过统一入口重新查询候选和检查到期提醒。

- Todo：补发休眠期间所有已经到点、仍未完成且仍有效的提醒。
- Event：仅当恢复检查时间严格早于实例结束时间时补发。
- 当恢复检查时间等于或晚于 Event 结束时间时，视为事件已结束，不补发。

正常轮询也使用相同规则，因此无需单独维护一套休眠补发算法。

## 统一协调器

在平台无关的应用层新增 `AlarmCoordinator`。它负责：

- 保存最后一次成功检查时间；
- 请求最新设置与提醒候选；
- 计算提醒时间和到期区间；
- 按 Todo/Event 补发规则过滤；
- 生成通知展示模型；
- 在通知成功后记录进程内去重键；
- 暴露统一的 `recalculate()` 入口。

Electron 组合根只负责：

- 每 30 秒调用协调器；
- 在系统恢复时调用协调器；
- 在成功的设置、日程或实例变更后调用协调器；
- 将格式化后的通知交给 Electron `Notification`。

以下成功变更必须触发同一个 `recalculate()`：

- 设置更新；
- 日程创建与更新；
- 日程软删除或恢复；
- 实例排除；
- Todo 完成或恢复为未完成。

评论、收藏和专注记录等不影响提醒候选的变更不触发重算。

## 候选查询与过滤

提醒候选通过应用端口获取，数据库适配器负责查询 Event 的开始时间或 Todo 的截止时间落在所需范围内的实例。查询范围必须覆盖上次成功检查时间、当前检查时间、配置的提前分钟数以及用于后续轮询的有限前瞻窗口。

数据库查询排除：

- 已完成实例；
- 已排除实例；
- 已软删除实例；
- 所属日程已软删除的实例。

协调器在通知前再次检查实例状态和相应类型的提醒开关。Todo 使用 `todoAlarmEnabled` 与 `todoAlarmBeforeMinutes`；Event 使用 `eventAlarmEnabled` 与 `eventAlarmBeforeMinutes`。没有 Event 开始时间或无有效目标时间的候选不通知。

设置或日程变更可能让新计算的提醒时间落在当前检查时间之前。重算时：

- Todo 若仍有效，则立即提醒；
- Event 若仍有效且当前时间严格早于结束时间，则立即提醒；
- 已结束 Event 不提醒。

该立即提醒同样受进程内去重控制。

## 通知展示

平台无关的纯格式化函数生成通知标题和正文；Electron notifier 不负责业务格式化。

标题格式：

- `Event: <日程名称>`
- `Todo: <日程名称>`

正文使用设置中的 IANA 时区转换时间，不读取操作系统默认时区，也不直接展示 ISO 字符串：

- Todo：可选非空备注，加上本地日期和截止时间；
- Event：可选非空备注，加上开始与结束的本地日期和时间；
- 跨日 Event 分别展示开始日期和结束日期，避免歧义。

时间的未知语义由 `KnownTimeMark` 保留：

- `11`：`09:30`
- `10`：`09:?`
- `01`：`?:30`
- `00`：`?:?`

日期使用稳定、可测试的数字格式，时区显式传给格式化函数。测试不得依赖机器 locale、日期或时区。

## 失败处理

- 候选或设置读取失败时不推进成功检查边界，下一次检查重试。
- 单条通知失败时不记录该提醒的去重键，以便后续重试。
- 一条通知失败不应把其他到期提醒误标为已通知。
- 调度错误通过 Electron 现有错误报告路径记录，不向 Vue 暴露 Electron 类型或异常对象。

## 测试策略

### 纯单元测试

- 验证 `(previous, current]` 两端边界；
- 验证连续轮询不会重复，定时器延迟不会永久漏发；
- 验证相同 `occurrenceId + alarmAt` 的重算去重；
- 验证 Todo 休眠期间全部补发；
- 验证 Event 仅在 `checkedAt < end` 时补发，并覆盖 `checkedAt === end`；
- 验证设置变化产生过去的提醒时间时立即提醒；
- 验证完成、排除、软删除和禁用提醒过滤；
- 验证通知失败后可重试；
- 验证用户时区、跨日 Event 与四种未知时间标记的通知正文。

### 数据库集成测试

- 验证提醒候选查询排除已完成、已排除、实例软删除和日程软删除的数据；
- 验证 Event 使用开始时间、Todo 使用截止时间进行范围查询；
- 验证查询范围边界与应用层左开右闭检查配合。

### Electron 集成测试

- 使用假的定时器、系统恢复端口和 notifier，不弹真实通知；
- 验证系统恢复触发统一重算；
- 验证设置更新、日程创建/更新/软删除、实例排除和 Todo 完成成功后触发统一重算；
- 验证失败的变更不触发重算；
- 验证 Electron notifier 只展示已经格式化的标题与正文。

## 非目标

- 不跨应用退出、重启或操作系统关机持久化投递状态；
- 不增加数据库提醒队列表；
- 不改变现有提醒提前分钟数的设置模型；
- 不引入 TanStack Query；
- 不把 Electron、Drizzle、SQLite 或宿主类型暴露给 Vue 组件。
