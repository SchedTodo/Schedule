# Database 旧版筛选还原设计

**日期：** 2026-07-15

## 背景

Schedule v2 的 Database 页面在迁移后增加了 Star 下拉和 Active/Deleted 下拉，导致筛选栏比旧版拥挤，并改变了旧版默认同时展示未删除和已删除日程的行为。本次调整以旧版 `src/renderer/src/pages/DatabasePage.vue` 和用户提供的旧版截图为基准，恢复旧版筛选交互，同时保留 v2 新增的日程恢复能力。

## 范围

- 筛选栏只保留搜索框、日期范围、Type 下拉和 Star 图标。
- 删除 Star 下拉以及 Active/Deleted 下拉。
- 默认查询同时返回未删除和已删除日程。
- 保留显式按删除状态查询的底层能力，供现有内部调用和测试使用。
- Restore 控件放在 Deleted 状态标签旁，仅已删除行显示。
- 不调整其他页面，也不进行无关的表格或样式重构。

## 查询契约

`ScheduleSearchQuerySchema.deleted` 从带 `false` 默认值的布尔字段改为可选布尔字段：

- 省略 `deleted`：返回未删除和已删除日程。
- `deleted: false`：只返回未删除日程。
- `deleted: true`：只返回已删除日程。

该语义让 Database 页面通过省略字段恢复旧版默认行为，同时保留现有精确查询能力。浏览器内存网关和 Electron SQLite 仓库必须实现相同语义，IPC 继续使用同一 Zod 契约验证输入。

## 页面交互

筛选栏顺序固定为：

1. 搜索框。
2. 日期范围。
3. Type 下拉。
4. Star 图标按钮。

Star 图标有两个状态：灰色表示不过滤星标，黄色表示只显示已星标日程。点击图标在这两个状态之间切换，并将页码重置为第一页后刷新数据。页面不提供“只看未星标”模式，以保持旧版行为。

页面查询不发送 `deleted` 字段，因此列表和总数都覆盖两种删除状态。其他筛选条件与分页继续由一次后端查询完成，不在前端合并结果。

## Restore 控件

Restore 使用低强调的恢复图标，紧邻 Deleted 状态标签，仅在 `item.deleted` 为 `true` 时出现。按钮提供可访问名称。点击按钮必须阻止表格行的详情跳转；恢复成功后刷新当前页，使状态和总数与持久层保持一致。

Star 单元格只展示星标状态，不再承载 Restore 控件。

## 错误处理

本次不新增错误展示机制。Restore 沿用当前平台调用行为：只有恢复调用完成后才刷新数据；平台失败时保留当前列表状态。查询输入继续由 Zod 在 Web 和 Electron 边界验证。

## 测试

按测试驱动方式覆盖以下行为：

- 契约允许省略 `deleted`，并保留显式布尔值。
- 浏览器内存网关在省略 `deleted` 时同时返回两种状态，在显式传值时正确过滤。
- SQLite 仓库具有相同的全部/未删除/已删除查询语义。
- Database 页面只有一个 Type `NSelect`，没有新增版 Star 和 Deleted 下拉。
- Star 图标在“全部”和“仅星标”之间切换，并触发正确查询。
- 已删除行的 Restore 图标位于 Deleted 单元格，点击后不跳转并刷新列表。

## 不采用的方案

- 不引入 `all | active | deleted` 枚举，因为可选布尔字段已经能表达所需语义，改动更小。
- 不在前端并行查询两种删除状态后合并，因为这会破坏统一排序、分页和总数。
